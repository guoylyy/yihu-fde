# 09 · 对接前待确认事项与系统侧建议

> 训练智能体之前，这些问题建议先确认/处理，否则智能体会在真实使用中碰壁。

## A. 需要产品/后端确认的问题

1. **Issue/Risk 创建权限**：后端当前把 `POST /projects/:id/issues|risks` 分别挂在 `issue.manage`/`risk.manage` 权限下，而 FDE_ENGINEER 默认没有这些权限——即"工程师上报问题/风险"这个高价值场景会 403。
   建议：给这两个接口单独放开权限（如新增 `issue.create`/`risk.create` 授予 FDE_ENGINEER），或训练材料按"引导转经理"处理（07 文档 S14/S15 目前按后者写）。
2. **工时创建默认状态**：当前创建即 SUBMITTED（无草稿暂存环节），智能体不做"保存草稿再提交"的两段式引导。若后端未来恢复 DRAFT 流程，07 文档相关话术需同步更新。
3. ~~**智能体的调用身份**~~ ✅ 已解决（2026-07-14）：采用代理用户模式 + API Key。后端已内置 MCP Server（见 10 文档），API Key 绑定用户、库存 sha256 哈希、可吊销。
4. ~~**Token 有效期与刷新**~~ ✅ 已解决：API Key 长期有效直至吊销，平台无需处理 token 刷新（MCP 服务端内部代发短期 JWT）。
5. **后端公网可达性**：后端 3005 端口目前无公网直连（README/交接文档记载），第三方平台要调 API 必须先解决：nginx 反代或 frp 隧道 + HTTPS + 域名。**这是对接的前置硬条件。**
6. **接口限频**：`backend/src/lib/ratelimit.js` 存在限频逻辑，确认智能体高频调用（如批量补工时）是否会触发，必要时给智能体来源 IP 加白。
7. **文件上传通道**：第三方平台能否转发用户上传的图片/文件到 `POST /api/fde/uploads`？若平台只支持 URL 透传，需确认七牛直传方案。

## B. 建议后端补充的"智能体友好"接口（可选，非阻塞）

| 建议 | 理由 |
|---|---|
| `GET /api/fde/timesheets/check?date=` 查某天是否已填工时 | 支持"昨天忘了填吗"类问询，现在要拉列表自己判断 |
| 批量创建工时接口 | "上周三到周五各8小时"目前要循环 3 次调用 |
| 统一的错误码文档 | 智能体错误话术映射更准确 |

## C. 验收智能体的建议测试集（上线前跑一遍）

1. 正常链路：S1-S21（见 07 文档）每个意图至少 1 条真实调用。
2. 权限负样本：用工程师账号触发 S22 全部越权场景，确认智能体不重试、话术正确。
4. 数据准确性：金额小数（45.5）、0.25 步进工时（7.75）、跨月日期换算、"上周五"边界（周一时说上周五）。
5. 多项目歧义：用户参与 2+ 项目时说"那个项目"，智能体必须列出候选而不是猜。
