# 07 · 对话训练语料：意图 → 槽位 → 工具调用

> 格式：每个样本含【用户话术】【意图】【槽位提取】【工具调用序列】【回复要点】。
> 话术覆盖口语化、省略、多轮补全、批量操作、异常处理五类。相对日期以会话当天为基准换算。

## 样本集

### S1 填工时 · 信息完整（单轮）

**用户**：帮我记下今天的工时，智慧工厂项目 8 小时，主要做产线数据采集接口的联调
**槽位**：project="智慧工厂"（需解析→projectId）、workDate=今天、hours=8、workContent="产线数据采集接口联调"
**调用**：
1. `GET /api/fde/projects?keyword=智慧工厂` → 取匹配项目 id（唯一命中直接用；多命中列出让用户选）
2. 向用户确认："记录：2026-07-14，智慧工厂项目，8h，产线数据采集接口联调，确认？"
3. `POST /api/fde/timesheets` body `{projectId, workDate:"2026-07-14", hours:8, workContent:"产线数据采集接口的联调"}`
**回复要点**：已提交，等经理审批；顺带播报本月累计工时。

### S2 填工时 · 信息缺失（多轮补全）

**用户**：记个工时
**智能体**：好的，三个信息一起告诉我：哪个项目、哪天、几小时？工作内容简单描述一下。（如你只在"智慧工厂"一个项目，我就默认它）
**用户**：还是那个项目，昨天，干了一天，调试报表
**槽位**：projectId=默认项目、workDate=昨天(2026-07-13)、hours=8（"一天"=8）、workContent="调试报表"
**调用**：确认后 `POST /api/fde/timesheets`

### S3 批量补工时

**用户**：上周三到周五我都在客户现场部署，每天8小时，帮我把工时补了
**槽位**：日期=2026-07-08/09/10、hours=8、workContent="客户现场部署"、location="客户现场"、project 需确认
**调用**：确认项目后循环 3 次 `POST /api/fde/timesheets`
**回复要点**：列一张 3 行小结表（日期/时长/状态）。

### S4 查工时审批状态

**用户**：我上周的工时批了没
**调用**：`GET /api/fde/timesheets?from=2026-07-07&to=2026-07-13`
**回复要点**：按状态分组汇报："5 条中 4 条已通过，周五那条还在等经理审批。"REJECTED 的要念出来并问是否现在修改重提。

### S5 任务播报（每日启动）

**用户**：我今天要干嘛
**调用**：
1. `GET /api/fde/me`（项目/待办/本月工时）
2. `GET /api/fde/notifications?unread=true`
**回复要点**：合并成简报：进行中任务、今天到期任务（dueDate=今天，高亮 URGENT/HIGH）、未读通知数、昨天工时是否已填（没填提醒补）。

### S6 推进任务状态

**用户**：数据清洗那个任务我做完了
**调用**：
1. `GET /api/fde/tasks?mine=true&keyword=数据清洗` → 定位任务 id
2. `POST /api/fde/tasks/:id/status` body `{status:"DONE"}`
**回复要点**：完成确认；如任务下还有未勾选子任务，提示"还有 2 个子任务没勾，要一起标完成吗？"

### S7 拆子任务

**用户**：给部署任务拆三个子任务：装环境、导数据、冒烟测试
**调用**：定位任务后循环 `POST /api/fde/subtasks` ×3（title 分别为三项，order 递增）

**调用**：

### S14 报问题

**用户**：记个问题：客户生产环境的推送接口经常超时，影响挺大
**槽位**：title="生产环境推送接口经常超时"、severity=HIGH（"影响挺大"）、project 需定位
**调用**：`POST /api/fde/projects/:id/issues`
**异常分支**：若返回 403（issue 创建挂 issue.manage 权限），回复："系统里问题登记需要经理权限，我帮你整理好了这段问题描述，直接转给经理录入：【…】"

### S15 报风险

**用户**：记个风险，客户测试数据一直没给，验收可能延期，概率挺高
**槽位**:title="客户测试数据未提供，验收可能延期"、probability=HIGH、impact=MEDIUM(可追问)、mitigation 追问："打算怎么应对？我把缓解措施一起记上。"
**调用**：`POST /api/fde/projects/:id/risks`（挂 risk.manage，403 处理同 S14）

### S17 知识沉淀（智能体起草）

**用户**：把这次数据库迁移踩的坑整理成知识库文章
**调用**：
1. 追问要点或从会话上下文提炼 → 按【背景/现象/排查/解决/预防】起草 Markdown
2. 用户确认后 `POST /api/fde/knowledge` body `{title, content, category, tags, projectId}`

### S18 知识检索

**用户**：有没有人写过飞书对接的文档
**调用**：`GET /api/fde/knowledge?keyword=飞书` → 命中列标题+分类，用户选择后 `GET /knowledge/:id` 输出摘要。

### S19 项目进展查询

**用户**：智慧工厂项目现在什么进展
**调用**：`GET /api/fde/projects/:id`
**回复要点**：状态/进度%/健康度 + 里程碑到哪一个 + 未关闭 Issue/Risk 数 + 我名下未完成任务。

### S20 越权请求（负样本）

**用户**：帮我把小王加进项目 / 帮我把这条工时审批了 / 查一下这个客户的全部项目
**回复要点**：不调接口或调用后拿 403，礼貌说明权限归属（经理/管理员/销售），主动提供替代（"我可以帮你起草给经理的申请消息"）。

### S21 状态冲突（负样本）

**用户**：把上周三那条工时改成 6 小时
**调用**：`GET /api/fde/timesheets?from=...` → 发现该条已 APPROVED
**回复要点**："这条已经审批通过，系统不允许修改。需要调整的话要请经理驳回后你再改，或者我帮你写一条说明发给经理。"

### S22 会话初始化（系统侧）

会话开始时智能体应静默执行：
1. 校验 token 有效（`GET /api/auth/me`），失效则引导登录
2. `GET /api/fde/me` 缓存：engineerId、我的项目列表（做项目名→ID 解析表）、进行中任务
3. 若用户只有一个在职项目，全会话默认该项目，减少追问

## 槽位归一化规则表

| 用户说法 | 归一化 |
|---|---|
| 一天 / 一整天 | hours=8 |
| 半天 | hours=4 |
| 今天/昨天/前天 | 当天日期 −0/−1/−2 |
| 上周N | 上一个自然周的周N |
| 吃饭/午饭/晚餐 | MEAL |
| 酒店/住宿 | LODGING |
| 请客/招待客户 | ENTERTAIN |
| 挺严重/影响很大 | severity=HIGH（CRITICAL 需用户明说"致命/全挂了"级别） |
| 大概率/很可能 | probability=HIGH |
| 做完了/搞定了 | status=DONE |
| 开始搞/在做了 | status=IN_PROGRESS |
