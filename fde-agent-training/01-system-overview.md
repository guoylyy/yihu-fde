# 01 · 系统概览与 FDE 工程师角色画像

## 系统是什么

**FDE 平台**：一套开源的**工程师与智能体协作交付系统**，覆盖 `创意/想法 → 立项 → 里程碑 → 任务 → 派工 → 交付` 的生产链，辅以工时与知识沉淀。

- 后端：Node.js + Express + Prisma ORM + MySQL 8，REST API，前缀 `/api/fde/*`（认证在 `/api/auth/*`）
- 认证：JWT Bearer Token，用户名/密码登录
- 文件：七牛云存储，统一上传口 `POST /api/fde/uploads`
- 通知：站内通知 + 飞书机器人推送

## FDE 是什么角色

FDE（Forward Deployed Engineer，现场部署工程师）是公司派驻客户现场/远程执行 AI 项目交付的工程师。他们的日常围绕**项目交付执行**展开：干活、记工时、报进度、报问题、沉淀知识。

## 系统角色体系（5 个内部角色）

| 角色 | 中文 | 定位 |
|---|---|---|
| `ADMIN` | 系统管理员 | 所有权限 + 用户管理 |
| `PLATFORM` | 平台运营 | 全局看板 + 所有业务数据 |
| `MANAGER` | 项目经理 | 管项目、审批工时、验收任务 |
| `FDE_ENGINEER` | **FDE 工程师（智能体服务对象）** | 填工时 + 执行任务 + 只看自己参与的项目 |
| `SALES` | 销售 | 客户档案与立项 |


## FDE 工程师在系统中的活动地图

```
每日：
  登录 → 看工作台(/api/fde/me) → 看任务/通知
  ├── 推进任务状态、勾子任务
  ├── 下班前填工时（项目 + 日期 + 小时 + 工作内容）

每周/节点：
  ├── 上报 Issue / Risk

低频：
  ├── 写知识库文章
  └── 更新个人档案技能
```

## 数据范围规则（智能体必须理解）

后端对 FDE_ENGINEER 做强制数据隔离（`buildScopeWhere`），**不是前端过滤，是后端 where 条件**：

- 项目：只能看到自己是成员（ProjectMember 在职记录）的项目

因此智能体不需要自己做权限判断兜底——后端会拦；智能体的职责是**遇到 403 时用人话解释**（"这个操作需要项目经理权限"），不要盲目重试。

## 关键身份概念：userId 与 engineerId 双轨

- `User` 是登录账号（userId），`Engineer` 是工程师档案（engineerId），一对一关联。
- 登录接口返回两个 ID 都有：`data.user.id`（userId）和 `data.user.engineerId`。
- 智能体应在登录/会话初始化时把两个 ID 都存进会话变量。

## 业务实体编号规则（用户可能用编号指代对象）

| 实体 | 编号格式 | 示例 |
|---|---|---|
| 项目 | `FDE-{年}-{4位序号}` | FDE-2026-0012 |

编号不连续是正常的（删除不回收序号）。用户报编号时可用列表接口 keyword 搜索定位 ID。

## 智能体总体行为准则建议

1. **先查后写**：所有写操作前先用列表/详情接口确认目标对象存在、状态允许该操作。
2. **必填数据收集齐再调接口**：缺什么问什么，一次问全，不要一条条挤牙膏。
3. **写操作前复述确认**：金额、日期、工时数这类关键数据，执行前用一句话跟用户确认（"确认记录：7月14日，XX项目，8小时，内容：数据对接调试？"）。
4. **相对日期换算**：用户说"今天/昨天/上周五"，换算成 YYYY-MM-DD 再入参。
5. **状态机意识**：已审批的不能改、已签发的不能删——遇到状态冲突向用户解释当前状态和可行路径。
7. **金额与工时敏感**：涉及钱和工时的数据，宁可多确认一次。
