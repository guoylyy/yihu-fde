# 多项目自动开发模式：接入指南

> 这套模式已在FDE 平台自身验证：AI 每 10 分钟巡检平台任务 → 自主开发 → 本地验证 → 提交关联 → 上线发布 → 回写留痕。本文教你把任何项目接入同样的模式。
> 配套阅读：[员工开发工作流：从零到交付](/docs/dev-workflow)（单人日常用法）。

---

## 1. 模式全景

```
🎙️ 开会 → 🧩 AI梳理需求 → 人确认 → 📋 生成任务
                                        ↓
   验收 ✅ ← 上线发布 ← 本地验证 ← AI巡检自动开发（每10分钟）
```

人负责：**开会提需求、确认需求、验收结果、拍板发布**。
AI 负责：**取任务、拆分、开发、验证、提交、回写、（按策略）发布**。

## 2. 五通道模型

一个项目能跑自动开发，取决于五个通道是否接通：

| 通道 | 说明 | 载体 |
|---|---|---|
| ① 任务源 | 项目有可执行的任务（描述写清做什么、怎么算完成），且已被 PM 排入生产队列（**QUEUED**，TODO 收件箱不进流水线） | 平台里程碑 + 任务（会议链路生成或手工建） |
| ② 取任务 | AI 能读写该项目的任务 | MCP + 专属 Key（数据范围 = 项目成员身份） |
| ③ 开发与验证 | AI 知道怎么跑起来、怎么验证 | 本地 checkout + **CLAUDE.md**（见第 4 节） |
| ④ 发布 | 一条命令可部署 + 可验证 + 可回滚 | 部署脚本/CI + 健康检查端点 |
| ⑤ 巡检驱动 | 定时触发 AI 拉任务干活 | 巡检 prompt（见第 5 节）挂定时器 |

## 3. 接入前提条件清单

**平台侧**（通用能力，逐项打勾即可）
- [ ] 项目已建，执行 AI 对应的账号**是项目成员**
- [ ] 代码仓库已登记到项目主页「代码仓库」Tab（commit 带 `#任务号` 才能自动挂回任务时间线）
- [ ] 有进行中的里程碑与任务（建议走 开会→需求→任务 链路，任务自带来源）
- [ ] 要自动开发的任务已由 PM 置为 **QUEUED（等候生产）**——自动开发只消化排队任务，TODO 收件箱由人筛选后排队，这是 PM 控制自动开发节奏的总闸

**代码侧**（每项目一次性投入，**最关键**）
- [ ] 本地有仓库 checkout，git push 权限就绪
- [ ] 仓库根目录有 **CLAUDE.md**（第 4 节模板）——没有它，AI 每轮都要从零摸索，质量与速度都打折
- [ ] 本地能启动并验证（依赖可本地化，或有测试环境）

**发布侧**（每项目一次性投入 + 一个拍板）
- [ ] 部署脚本化（一条命令），凭证给到执行 AI
- [ ] 有健康检查 URL（发布后用它验证）
- [ ] **发布策略已拍板**（第 6 节）——客户项目默认不自动上线

**巡检侧**
- [ ] 项目加入巡检清单（第 5 节 prompt 按项目参数化）
- [ ] 用 1~2 个小任务试运行全链路并验收通过

## 4. CLAUDE.md 标准模板

复制到项目仓库根目录，按实际填写。**发布策略一行必填**。

```markdown
# <项目名> 开发指南（CLAUDE.md）

## 项目概况
- 平台项目：#<平台项目ID> <项目名>（客户：<客户名>）
- 一句话业务：<这个系统给谁解决什么问题>
- 技术栈：<如 Vue3 + Express + Prisma + MySQL>
- 仓库：<git 地址>（平台代码仓库 Tab 已登记：是/否）

## 本地启动
- 依赖：<node 版本 / mysql / redis / 其他中间件>
- 配置：<.env 从哪来、关键变量说明、敏感项找谁要>
- 启动：<后端命令 → 端口；前端命令 → 端口>
- 测试账号：<账号/密码/角色>（仅测试环境）

## 验证方式
- 构建检查：<如 npm run build>
- 自动化测试：<命令；没有就写"无，靠手工"|
- 手工验证要点：<改动后必须点哪些核心流程>
- 测试环境：<地址；与生产的差异>

## 部署
- 方式：<deploy.sh / Jenkins 任务名 / 其他>（入口与凭证：<在哪/找谁>）
- 数据库迁移：<自动跑/手动跑/无迁移>
- 健康检查：<URL>
- 回滚：<怎么回滚上一版>
- **发布策略：自动上线 ｜ 需主人验收后上线**（客户生产环境默认后者）

## 已知坑
- <环境坑/数据坑/业务红线，一条一行，持续累积>

## 业务约定
- <命名规范/分支策略/该项目特有的红线，如"供应商不允许物理删除">
```

## 5. 巡检 prompt 参数化模板

把下面模板中的 `<>` 参数替换后挂到定时器（如 Claude Code 的 `/loop 10m <prompt>`）：

```
自动开工巡检（<项目名>·项目<平台项目ID>）：按 fde-tasks 工作流执行。
⓪每轮开始调用 report_presence 上报心跳：{"projectId":"<平台项目ID>","activity":"巡检<项目名>: <一句话>"}
①查项目<ID>进行中的里程碑与其下 **QUEUED（等候生产）** 任务（没有里程碑的项目直接查项目 QUEUED 任务）——TODO 是需求收件箱，未经 PM 排队不自动开发，**无 QUEUED 任务时不要拉 TODO 兜底**；
②只处理「未指派」或「指派给我」的任务，别人的任务不动；用户显式指定任务 ID 或明示"处理收件箱某任务"时不受 QUEUED 限制；
③无排队任务本轮安静结束（回复一句"巡检无排队任务"即可）；
④有任务按 URGENT>HIGH>MEDIUM>LOW 逐个开发：置IN_PROGRESS→**立即 report_presence 带 taskId**（{"taskId":"<任务ID>","activity":"<一句话>","phase":"读代码"}，有明确进度可带 progress，纯巡检不确定进度就不要传）→拆子任务→开发→按 CLAUDE.md 验证→commit 带 #任务号 推送→**任务完成/放弃时 report_presence 传 {"taskId":null} 清空**→评论汇总→置DONE；
⑤做不了的（要拍板/缺依赖/权限不足）不改状态，先 report_presence 清空 taskId、评论标注原因后跳过；
⑥发布按 CLAUDE.md 的发布策略：自动上线项目走部署脚本+健康检查+写 CHANGELOG；需验收项目建「生产验收」任务等主人点头；
⑦红线：不可逆操作不做、验收是人的动作、工时金额不主动写、遵守 CLAUDE.md 业务约定。
⑧被禁即停（v2.12.1 #1284）：任何调用返回 401「API Key 无效或已吊销」或 403 code 9030「机器人档案已被禁用/已注销…请立即停止」→ **本轮立即终止、退出循环、不重试、不重复上报**（恢复需主人或管理员在平台重新启用；进行中的运行允许 complete_dev_run 收尾一次）。
```

> ⓪的心跳让平台任务看板能实时展示「哪些 agent 正在巡检」（v2.0.9）。v2.12 起心跳可带 `taskId/phase/progress`，让「哪个任务正被哪个 agent 开发」可见；无进度的巡检不要硬传 progress——前端会如实显示「巡检中」而不是假进度。巡检终止时补一次 `{"status":"OFFLINE"}`。

## 6. 发布策略分级（必须拍板）

| 级别 | 适用 | AI 行为 |
|---|---|---|
| **自动上线** | 内部平台、自有产品 | 开发完成→部署→健康检查验证→写 CHANGELOG，全自动 |
| **验收后上线** | **客户生产环境**（默认） | 开发完成→commit→建「生产验收」任务附改动摘要与部署步骤，人点头后 AI 再执行部署 |
| 仅开发 | 敏感系统/无部署通道 | 只到 commit + 回写，部署完全人工 |

客户项目选「验收后上线」的理由：出事代价不同、合同范围需要人把关（防范围蔓延）、客户感知需要经理控制节奏。

## 7. 接入五步流程

1. **平台**：加成员 → 登记仓库 → 开一场会把首批需求梳理成任务
2. **本地**：clone 仓库 → 按模板写 CLAUDE.md → 人带 AI 手动走通一次「取任务→开发→验证→commit 回写」
3. **发布**：给部署方式与凭证 → 准备健康检查端点 → 拍板发布策略并写入 CLAUDE.md
4. **巡检**：按模板生成该项目巡检 prompt，挂定时器
5. **试运行**：用 1~2 个小任务跑全链路 → 人验收 → 通过后放量

## 8. 规模化的两条路

- **横向**：一个 AI 巡检多个项目（适合纯内部项目，集中托管）
- **纵向**：每个项目配责任人，责任人用「开发上手」配置包让自己的 Claude Code 跑同样流程（**客户项目推荐**——有人对结果负责，AI 是加速器）

两条路共用同一套平台链路（任务/MCP/提交关联/验收），按项目性质选择即可。
