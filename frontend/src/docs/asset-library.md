# 资产沉淀与复用指南

> v2.7 · 做过的东西，下一个项目直接拿来用

交付效率低，很大一部分原因是**同样的东西在不同项目里反复重做**。我们盘点过自己的代码仓库：后台骨架做了约 9 遍，大模型接入做了 7 遍，产品报价规则引擎做了 6 遍以上。「资产库」就是为了让这种事不再发生。

## 什么算资产

一句话：**另一个项目可以直接拿走用，并且能省下至少 1 人天。**

| 层 | 是什么 | 例子 |
|---|---|---|
| 项目框架 | 新项目的起点 | 后台骨架、移动端模板、部署模板 |
| 架构能力 | 和业务无关、每个项目都要的技术能力 | 微信生态套件、大模型网关、MCP 服务模板、审批引擎 |
| 业务能力 | 能跨客户复用的业务功能块 | 快递比价、配置化报价引擎、打卡激励引擎 |

每个资产带三类东西：

- **数据**：业务对象定义（对象 / 属性 / 关系 / 动作），也就是本体的雏形
- **方案**：解决什么问题、适用与不适用、接入步骤、坑
- **界面**：可运行的页面组件、截图、演示

不算资产的：只对一个客户成立的逻辑、一次性脚本、平台自带的功能。做法类经验进「Skills 能力包」，坑与口径进经验库。

## 成熟度：先登记，第二次用时再抽离

| 级别 | 含义 | 怎么复用 |
|---|---|---|
| **L0 线索** | 一句话 + 出处 | 找负责人要源码参考 |
| **L1 可参考** | + 脱敏方案 + 关键文件清单 | 照着源码改 |
| **L2 可复制** | 代码已抽离进资产仓库，有测试 | 拷目录、改配置 |
| **L3 可安装** | 独立包 / 独立服务 | 安装即用 |

规则：**登记门槛极低，抽离按需发生。** 做完一个觉得别人也能用的东西，花 5 分钟登记成 L0 就行；等第二个项目真要用时，才由那个项目把代码抽离、脱敏、升到 L2。被 3 个项目复用过，就考虑做成 L3 并上架商城模块。

## 开发前：先搜一搜

- **资产库页面**（后台「项目交付 → 资产库」）按关键词、层、成熟度、行业、技术栈筛选
- **任务详情**会自动显示「可能用得上的资产」（按任务标题和描述匹配）
- **AI 开发**：`get_task` 返回体里带 `suggestedAssets`；也可以主动调 MCP 工具 `search_assets(taskId=…)`，再 `get_asset(asset='…')` 看完整方案与数据结构

授权标记要看清：

| 标记 | 含义 |
|---|---|
| 自研 | 可以直接复用代码 |
| 客户已授权 | 客户确认过通用部分可复用 |
| **仅参考** | 来自客户项目，只能参考思路，**不要整段拷贝客户代码** |

## 用上了：登记复用

资产页点「我用上了 · 登记复用」，或让 AI 调 `record_asset_usage`：选项目、关联任务、怎么用的（照着改 / 拷目录 / 安装）、省了几人天、有什么反馈。

**这是整个资产库最重要的一个动作。**没有复用记录，就说不清资产库到底省了多少，也没法判断哪个资产该升级、哪个该淘汰，商城模块的报价也没有依据。

## 做完了：登记资产

- **随手登记**：资产库页「登记资产」，工程师登记的一律进草稿，经理审核后发布
- **项目收尾**：关闭项目时勾选「同时从本项目起草可沉淀资产」，或在项目页「资产」Tab 点「从本项目起草资产」——AI 从完成的任务和收工回写里挑出可复用的部分生成草稿，经理决定留不留
- **AI 提议**：开发中发现可复用的东西，AI 可以调 `propose_asset` 登记草稿

### 脱敏是硬门槛

方案、数据结构、截图里不能出现：客户名称与简称、域名与 IP、密钥与 token、人名与手机号、真实业务数据。发布时系统会自动扫描：**密钥样式一律拦截**；出现客户名会提示，经理确认可公开后才能强制发布。出处（源项目、源仓库、关键文件）另有内部字段记录，不必写进方案。

## 数据产物怎么写（本体）

每个业务资产附一份业务对象定义：

```yaml
shared: [Region]                 # 引用公司统一定义的核心对象，不重复定义
objects:
  - name: ShipmentQuoteRequest
    label: 快递询价
    properties:
      origin:   { type: ref, ref: Region, label: 寄件地, required: true }
      weightKg: { type: decimal, label: 总重量(kg) }
links:
  - { from: ShipmentQuoteRequest, to: CarrierQuote, cardinality: one-to-many }
actions:
  - { name: compareQuotes, input: ShipmentQuoteRequest, output: "CarrierQuote[]", mcpTool: compare_express_price }
```

客户、联系人、报价单、订单、合同、审批、地区这类对象全公司只定义一次（共享核心对象）。第二个资产要用同一个对象时，就把它提到共享层。资产攒够了，这就是公司的业务本体目录——做本体时不用从零开始。

## 资产仓库（L2 及以上）

抽离出来的代码统一放在 `资产仓库` 仓库，每个资产一个目录：

```
biz/express-quote/
  asset.json      元数据
  README.md       方案
  ontology.yaml   数据产物
  server/ ui/ seed/ test/ screenshots/
```

仓库自带校验（必填字段、授权与成熟度口径、本体引用、密钥扫描），生成 `catalog.json` 后由平台同步：资产元数据、方案、数据结构、截图自动更新到资产库，并为每个资产生成一个「复用资产」能力包，经理启用后 AI 开发时可以直接加载接入步骤。
