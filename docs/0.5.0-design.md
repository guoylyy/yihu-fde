# FDE 0.5.0 设计：开发团队操作台 + 会话回流

> 作者：JeffDD ｜ 2026-11-18 ｜ 目标版本 0.5.0（分三期，每期可单独验收）
> 一句话：**把 FDE 从「项目台账」改成「开发团队每天真正会打开的操作台」，并把开发过程（会话）收回来，做成可复用的经验。**

---

## 一、先说实话：现在的问题不是功能少，是「该有的没有，有的没人用」

我查了平台真实库（`app_fde`）各模块的数据量：

| 模块 | 数据量 | 判断 |
|---|---|---|
| 任务 tasks / 里程碑 / 项目 / 工时 | **97 / 28 / 6 / 50** | 真在用 |
| 周 OKR | 19 个 O | 刚上线，在用 |
| 工程师 engineers / 客户 / 项目记录 | 6 / 3 / 13 | 骨架有，内容少 |
| 技能 skills | **0** | 空 |
| 想法 ideas / 资产 assets | **0 / 0** | 空 |
| Agent 会话 / 派工 | **1 / 0** | 等于没做 |
| 通知 | 0 | 没触发过 |

也就是说：**20 多个菜单里，真正有数据的是 5 个**。他现在的感受「比较简单、不实用」是准确的——不是功能不够，是一堆功能填不满，而每天要用的那件事（我今天该干什么、这周谁忙谁闲、上次这个坑谁踩过）没有入口。

---

## 二、0.5.0 三根支柱

```
A 做减法     菜单从 20+ 项收到 5 组，0 数据的模块合并或下线
B 团队管理   人 → 负载 → 承诺 vs 交付 → 能力矩阵（本期核心）
C 会话回流   开发会话自动进平台 → 关联项目/任务 → 抽成经验（本期新能力）
```

---

## 三、A｜做减法：导航重排成 5 组

| 组 | 页面 | 来源（合并/新建） |
|---|---|---|
| **今日** | 我的今日（任务/到期/等我审/本周 OKR 进度） | workbench 改造，新建 |
| **团队** | 成员卡片 / 负载看板 / 周 OKR（我的、团队）/ 能力矩阵 | 合并 engineers + engineer-profiles + skills + okr/team |
| **交付** | 项目 / 任务 / 里程碑 / 工时 / 交付物 | 保留，project-records 并入项目详情 |
| **经验** | 经验库（知识、会话、决策、踩坑统一成"条目"）/ 检索 | knowledge + ideas + assets 合并，新增会话 |
| **设置** | 用户 / 角色 / Agent 档案 / API Key / 模型 / 审计 | 保留 |

- **下线**：`想法`、`资产`（各 0 条数据）→ 作为「经验条目」的类型存在，不再单独占菜单；
- **合并**：`技能 skills`（0 条）→ 并进「能力矩阵」，人工标注 + 自动派生；`我的机器人` 并入 Agent 档案；
- 目标是**一级 5 组、二级 ≤ 12 项**，手机上不需要滑两屏找菜单。

## 四、B｜核心开发团队管理（本期核心）

四个页面，都围绕「这周这个人该干什么、干得怎么样」。

### 1. 成员卡片（一人一页）
角色、技能（等级）、本周承诺（OKR 的 O）、手上的任务数、最近一次交付、最近活跃（会话次数/最后提交时间）。
**用来回答**：这个人本周是不是压满了、有没有人手上没活。

### 2. 负载看板（人 × 周）
一行一个人，列：进行中任务数 / 本周预计工时 / 本周承诺权重 / 实际会话时长。超过阈值标黄，两天没动过的标红。
**不做**排班、不做工时审批——那是另一个系统的事，这里只做"看得见"。

### 3. 承诺 vs 交付（老板视角最重要的一屏）
把三份数据摆在一起：**他说要做（周 OKR）｜ 系统里做了（任务闭环）｜ 实际干了多少（会话时长、提交数）**。
差异就是管理信号：承诺了但没任务 = 只在嘴上；有任务但没会话 = 卡住了或在别处干；会话很多但任务没闭环 = 方向在漂。
这一屏**只给老板和管理员**，工程师看不到别人的。

### 4. 能力矩阵（技能 × 人 × 等级）
- 人工标注：等级 1–5、最近使用时间；
- 自动派生：从会话里出现的仓库/语言/框架统计（只做候选，人工确认后才算数）；
- 用途：接新项目时看谁能上；某个技术只有一个人会 = 单点风险，标出来。

**明确不做**：不做排名、不做红黑榜、不做绩效分（老板 11-17 定的口径）。

## 五、C｜全生命周期会话回流（0.5.0 最关键的新东西）

### 要解决的问题（口径已按老板 11-18 的补充修正）

不只是「写代码时的 AI 会话」，而是**一件事从需求到上线，所有跟 AI 的对话都要回到平台**：

```
需求阶段   跟 AI 讨论需求边界、拆解、口径确认（Hermes / ChatGPT / Claude / 平台助手）
开发阶段   Claude Code / Codex 里的实现、调试、返工
测试阶段   测试单生成、缺陷分析、复验会话
上线/复盘  发版、事故复盘、经验总结
```

现在这些对话全散在各处：飞书里跟我聊的、终端里 Claude Code 跑的、网页版 ChatGPT 里问的。结果就是——**平台只知道"最后交付了什么"，完全不知道"为什么这么定、试过哪条路不通、谁在什么时候说过什么"**。同一个坑下个项目再踩一次，客户问"当初为什么不做 X"也说不清。

### 核心概念：会话挂到「阶段」上，串成一条线

一条会话不再只是一个聊天记录，它带三个坐标：**属于哪个项目 / 哪个阶段 / 关联哪张单据**。

```
project ─┬─ stage=REQUIREMENT   需求会话 ──→ 需求文档 / 需求条目
         ├─ stage=DESIGN        方案会话 ──→ 技术方案 / 决策记录
         ├─ stage=CODING        编码会话 ──→ 提交 / 分支 / 任务
         ├─ stage=TEST          测试会话 ──→ 测试单 / 缺陷
         └─ stage=RETRO         复盘会话 ──→ 经验条目
```

串起来之后，"一个需求的一生"就能一屏看完：谁先提的、AI 建议了几种方案、最后选了哪个、代码怎么落、测出什么问题、上线后怎么复盘。**这才是能抽业务经验的东西**，单看编码会话只能抽技术经验。

### 采集通道（四个，按落地成本排序）

| 通道 | 覆盖阶段 | 怎么采 | 成本 |
|---|---|---|---|
| 平台内 AI 助手 | 需求 / 方案 / 测试 / 复盘 | 本来就在平台里跑，直接落库（已有 `agent_conversations`，扩字段即可） | 无 |
| Hermes（我） | 需求 / 方案 / 测试 / 复盘 | 我按项目把会话摘要 + 决策点推给 FDE（`POST /api/devlog/conversations`），你跟我说过的口径、我做的验证都带过去 | 低（我这边加一个上报工具） |
| Claude Code / Codex | 编码 | `Stop` hook 或日志解析 → 本地采集器 `yh-devlog` 批量上传 | 中（要装一次） |
| 网页版/别处的对话 | 任意 | 「粘一段对话 → 自动结构化」：粘贴原始对话，AI 抽决策/坑/结论，人工确认后落库 | 低（兜底方案） |

前两个是主力（你 90% 的需求讨论其实发生在我这儿和平台助手里），Claude Code 是编码侧的主力，粘贴是兜底——**任何一段对话都能进平台，不要求非得走某个工具**。

### 每段会话落什么

```
元数据    会话 uid（幂等）、来源工具、模型、起止、轮数、token/费用、参与人
坐标      project / task / milestone / defect / stage（阶段）
内容      自动摘要 3–5 句 + 决策点 + 踩坑点 + 结论（AI 抽，人工可改）
产出      提交 sha、分支、改了哪些文件（路径不含内容）、生成的文档/测试单
标签      技术栈、业务域、问题类型
```

**正文默认不存**：只存摘要与元数据，需要时按单条会话显式开启（团队约定）。客户代码、密码、密钥、真实业务数据永不出本地。

### 从中抽经验（这是回流的目的，不是副产品）

1. **单个会话 → 经验条目**：任选一段（"这个报错怎么解的"）→ 生成「现象 / 原因 / 解法 / 适用场景」；
2. **跨阶段对齐 → 管理信号**（最值钱）：
   - 需求会话里说过"本期不做 X"，测试/开发里又冒出 X → 标记「口径漂移」；
   - 同一类坑在 ≥2 个项目出现 → 标记「流程问题」，不是个人问题；
   - 需求讨论里老板明确否掉的方案，后来又被实现 → 这类对照只有把四个阶段的会话放在一起才做得出来；
3. **每周一自动出一份「上周经验摘要」**：新踩的坑、可复用的做法、重复出现的问题、口径漂移清单。

### 检索

按 项目 / 阶段 / 人 / 技术栈 / 时间 / 关键词。典型问法：
- 「这个报错以前谁遇到过」→ 给会话 + 当时的解法；
- 「客户为什么不要这个功能」→ 给需求阶段那段对话原文摘要；
- 「上次这个项目怎么验收的」→ 给测试阶段会话 + 测试单 + 缺陷清单。

### 红线（写死）

```
① 客户代码 / 密钥 / 真实业务数据永不出本地；采集器只发摘要与元数据
② 正文默认不存；开启是逐条显式动作，且记录"谁开的"
③ 会话归属人可见自己的全部；老板/管理员默认只看摘要与统计，不看正文
④ 采集器随时可停（停了不影响开发），停了要在平台上看得出"从几号开始没数据"
```

## 六、数据模型草案

```sql
dev_conversation        id, uid(幂等键), source(PLATFORM_ASSISTANT|HERMES|CLAUDE_CODE|CODEX|PASTE),
                        stage(REQUIREMENT|DESIGN|CODING|TEST|RETRO),
                        engineer_id, project_id, task_id, milestone_id, defect_id,
                        model, started_at, ended_at, turns, tokens, cost, branch, cwd,
                        summary, decisions(json), pitfalls(json), tags(json),
                        commit_shas(json), body_stored(bool), status(PENDING_LINK|LINKED|IGNORED)
dev_conversation_event  id, conversation_id, seq, kind(DECISION|PITFALL|COMMAND|ARTIFACT|NOTE|QUOTE),
                        text, files(json), commit_sha, occurred_at
dev_experience          id, title, kind(EXPERIENCE|DECISION|PITFALL|HOWTO|DRIFT),
                        body, project_id, conversation_id, tags, reusable_level(1-3), created_by
engineer_capacity       engineer_id, week_start, planned_hours, committed_weight, actual_hours, load_pct
skill_matrix            engineer_id, skill, level(1-5), source(MANUAL|DERIVED), last_used_at
```

接口：

```
POST /api/devlog/conversations                批量上报（按 uid 幂等，允许重放）
POST /api/devlog/conversations/{id}/link      关联 项目/任务/里程碑/缺陷/阶段
POST /api/dev/conversations/{id}/summarize    AI 摘要 + 抽决策/坑（模型不可用降级规则）
POST /api/dev/conversations/paste             粘贴一段对话 → 结构化草稿（兜底通道）
GET  /api/dev/conversations?project=&stage=&engineer=&from=&tag=
GET  /api/projects/{id}/timeline              一个需求的一生（需求→开发→测试→复盘）
POST /api/experience/from-conversation        抽成经验条目
GET  /api/team/capacity?week=
MCP 工具：capture_conversation / link_conversation / search_experience / project_timeline / today
```

## 八、老板已拍板（2026-11-18 夜）

| 议题 | 决定 | 落地方式 |
|---|---|---|
| 会话内容存多少 | **正文也要存** | `dev_conversations.body` 存 messages；入库前脱敏（`sk-`/`Bearer`/`password=`/私钥块/mysql 连接串），命中记 `body_redacted`；列表默认不带 body，详情才返回 |
| 经验库与 Obsidian | **FDE 写、单向同步到 Obsidian** | `07.FDE经验/<项目>/<日期>-<标题>.md`，带 frontmatter；只写不读，重复同步覆盖同一文件 |
| 团队规模 | **会超过 15 人，现在就要留位** | 新增内置角色 `TEAM_LEAD`（dataScope=TEAM）：能看本组、**不能评分**（评分仍只 ADMIN）；`team.view` / `team.view.all` 两个权限点 |
| 工时 | **降级成任务字段** | `Task.actual_hours`；工时页面从菜单移除、路由保留并提示「已并入任务」；不删表不迁数据 |

## 九、明确不做的（免得越做越大）

```
不做 排班 / 工时审批 / 请假       —— 那是 HR 的事
不做 绩效排名 / 红黑榜           —— 老板已定：不排名
不做 代码托管 / CI / 代码评审    —— GitHub 已经在做，平台只做索引
不做 会话正文的全文检索          —— 默认只有摘要可检索
```
